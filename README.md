# بوت تنزيل الوسائط لتلغرام

هذا المشروع يشغّل بوت تلغرام باللغة العربية لتنزيل **المحتوى العام المسموح به** من TikTok وInstagram وFacebook وSnapchat وPinterest. تستقبل الخدمة تحديثات تلغرام عبر Webhook آمن، بينما تظل لوحة الإدارة داخل البوت وحصرية للمالك الأساسي. الموقع المصاحب لا يضم لوحة مستخدمين؛ وظيفته فقط إتاحة مسار Webhook وحالة الإعداد.

## بنية العمل

| العنصر | السلوك |
| --- | --- |
| استقبال التحديثات | `POST /api/telegram/webhook` مع التحقق من رأس السر الخاص بتلغرام. |
| فحص الرابط | يقبل HTTPS من المنصات المدعومة، ويقبل Pinterest Pin فقط. تُرفض الروابط الخاصة أو غير المتاحة برسالة واضحة. |
| الصور العامة | يبحث عن روابط الصورة الأصلية ضمن بيانات المصدر والصور الدوارة، ويزيل التكرارات ويفضل أعلى جودة متاحة. يدعم رابط TikTok من نوع `photo` عبر التطبيع الداخلي. |
| التنزيل | يعمل محرك `yt-dlp` و`ffmpeg` داخل صورة التشغيل. لا تُخزن بايتات الوسائط في قاعدة البيانات. |
| الخصوصية | ملف الوسائط في مجلد مؤقت، ويُحذف بعد الإرسال أو الفشل. كما تُحذف سجلات المهمة المنتهية فوراً. |
| لوحة المالك | لوحة أزرار سفلية تظهر فقط للمالك الأساسي المحدد في `OWNER_ID`. الملاك الإضافيون يتلقون التنبيهات ولا تظهر لهم لوحة التحكم. |
| التنظيف | مسار دوري محمي: `POST /api/scheduled/telegram-cleanup` لحذف المستخدمين غير النشطين والعمليات المنتهية وسجلات الأخطاء القديمة. |

## الأسرار المطلوبة

لا تضع أي قيمة في ملفات المشروع أو المستودع. أضف القيم من شاشة أسرار المشروع فقط.

| المتغير | الصيغة والمصدر |
| --- | --- |
| `BOT_TOKEN` | توكن البوت من [BotFather](https://t.me/BotFather). |
| `OWNER_ID` | معرّفك الرقمي في تلغرام، مثل `123456789`. لا تستخدم `@username`. |
| `WEBHOOK_SECRET` | اختياري. يشتقه المشروع تلقائياً وبصورة مستقرة من سر الخادم وتوكن البوت؛ لا يحتاج المالك إلى إضافته. |
| `WEBHOOK_URL` | اختياري. يشتقه المشروع عند التفعيل من نطاق النشر العام؛ لا تحتاج إليه عند التفعيل من نطاق المشروع المنشور. |

> لا تضف توكن BotFather في المحادثة أو في README أو ضمن متغيرات الواجهة الأمامية `VITE_*`.

## التشغيل بدون قاعدة بيانات

يعمل البوت بحالة داخلية في الذاكرة (المستخدمون، المهام، الملاك، الإحصاءات، المطالبات) ولا يحتاج MySQL للتشغيل. متغير `DATABASE_URL` اختياري ومخصص فقط لمسار تسجيل دخول الواجهة عند الحاجة، ويمكن تجاهله كلياً لتشغيل بوت التنزيل. تُفقد الحالة عند إعادة تشغيل العملية، وهذا مقصود لبوت لا يحتفظ ببيانات المستخدمين.

| المتغير | الوصف |
| --- | --- |
| `PORT` | منفذ الخادم (افتراضي `3000`). |
| `TRUST_PROXY` | `1` أو `true` للثقة ببروكسي واحد خلف HTTPS، أو رقم يمثل عدد الوكلاء. |
| `USE_CUSTOM_BUTTON_EMOJI` | `1` لتفعيل أيقونات الإيموجي المخصصة على الأزرار (يتطلب حساب Telegram Premium للمالك). |
| `BUTTON_CUSTOM_EMOJI_DOWNLOAD` / `BUTTON_CUSTOM_EMOJI_AUDIO` / `BUTTON_CUSTOM_EMOJI_IMAGE` / `BUTTON_CUSTOM_EMOJI_CANCEL` | معرّفات الإيموجي المخصصة لكل زر عند التفعيل. |

## أزرار ملونة

تستخدم أزرار الرد والأزرار المضمّنة الحقل `style` من Bot API الحديث (`primary` / `success` / `danger`)، فتبدو واضحة وسريعة على جميع إصدارات تطبيق تلغرام. الأزرار النصية تعمل دائماً، والإيموجي المخصص اختياري ولا يظهر إلا عند ضبط المتغيرات أعلاه.

## التشغيل المحلي للتجربة

لا تحتاج نطاقاً عاماً ولا HTTPS للتجربة. شغّل وضع الاستعلام المحلي (Long Polling):

```bash
pnpm install
copy .env.example .env
# ضع BOT_TOKEN و OWNER_ID في .env، ثم أضف: TELEGRAM_POLLING=1
pnpm dev
```

يفتح الخادم على `http://localhost:3000`، ويحذف وضع الاستعلام أي Webhook سابق ثم يستقبل التحديثات عبر `getUpdates`. أرسل `/start` إلى البوت لتظهر لوحة المالك الأساسي. لتنزيل الوسائط فعلياً يجب توفر `yt-dlp` و`ffmpeg` في `PATH`؛ بدونهما تعمل الواجهة والأوامر ولوحة المالك لكن التنزيل سيفشل برسالة واضحة. عند العودة للنشر العام أزل `TELEGRAM_POLLING` حتى لا يتعارض مع الـ Webhook.

## تفعيل Webhook بعد النشر

انشر المشروع أولاً من زر **Publish** في واجهة المشروع. لا يحتاج النشر الاعتيادي إلى إضافة `WEBHOOK_SECRET` أو `WEBHOOK_URL`؛ يشتق المشروع الأول من أسرار الخادم ويستخرج الثاني من نطاق الطلب المنشور. للتحقق من اكتمال الأسرار، افتح:

```text
GET /api/telegram/status
```

افتح الصفحة المنشورة مرة واحدة بعد اكتمال الحالة. ينفّذ الموقع من نفس النطاق طلب تفعيل مؤمناً، ويستخرج رابط Webhook من نطاق النشر. لا توجد قيمة سرية تذهب إلى المتصفح أو تُسجل في قاعدة البيانات، ولا يعمل طلب التفعيل في بيئة التطوير أو من نطاق خارجي.

> **حالة التحقق:** تم التحقق محلياً من اعتماد Telegram، ومن رفض الطلبات غير المصرح بها لمسارات Webhook والتفعيل. أما الاختبار الكامل الذي يثبت أن Telegram يرسل التحديثات فعلاً إلى نطاق HTTPS العام، فيبقى **معلّقاً إلى ما بعد النشر الفعلي**. بعد النشر، افتح صفحة الحالة مرة واحدة، ثم أرسل `/start` إلى البوت وتحقق من تغيّر حالة رابط Webhook إلى «مُعد» ومن وصول رسالة الترحيب.

## التنظيف الدوري بعد النشر

المشروع يتضمن معالج التنظيف فقط. بعد النشر، أنشئ مهمة يومية واحدة من بيئة المشروع:

```bash
manus-heartbeat create \
  --name telegram-daily-cleanup \
  --cron "0 0 3 * * *" \
  --path /api/scheduled/telegram-cleanup \
  --description "تنظيف مستخدمي البوت غير النشطين والمهام المؤقتة يومياً"
```

يعمل الوقت بتوقيت UTC. يمكن تعديل مدة عدم النشاط من لوحة المالك بأمر `/cleanup_days 30` ضمن نطاق 7–365 يوماً. لا يمسح التنظيف حساب المالك الأساسي أو الملاك الآخرين.

## لوحة المالك الأساسي

تظهر للمالك الأساسي فقط لوحة أزرار سفلية تُنظّم في **صفحات** مع أزرار «↩️ رجوع» و«🏠 الرئيسية»:

- **لوحة البداية**: زر «🚀 تشغيل البوت»، الإحصاءات، إدارة المستخدمين، الاشتراك الإجباري، الإعدادات، تنظيف البيانات، رسالة جماعية، الأخطاء الحديثة.
- **إدارة المستخدمين**: آخر المستخدمين، النشطون، غير النشطين، المحظورون، حظر وفك الحظر.
- **الاشتراك الإجباري**: إضافة/إزالة قناة أو مجموعة أو بوت يجب الاشتراك فيه لاستخدام الخدمة.
- **الإعدادات / التنظيف**: مدة عدم النشاط وتنظيف فوري.
- **الحدود والاشتراك (مدفوعة بالنجوم)**: حد تنزيلات لكل نافذة زمنية أو وضع مجاني بلا موعد، فتح/إغلاق الوضع المدفوع، وإنشاء حزم اشتراك (اسم + مدة بالأيام + سعر بالنجوم ⭐) وإيقافها. عندما يستنفد المستخدم حصته يظهر له زر «اشترك» يفتح فاتورة Telegram Stars، وعند نجاح الدفع تُفعَّل الاشتراكات تلقائياً وتُفتح الحصة بلا حدود. بيانات الحزم والاشتراكات محفوظة في مجلد `data/` وتبقى عبر إعادة التشغيل.

عند اختيار إجراء يحتاج رقماً أو نصاً، يطلب البوت القيمة التالية مباشرة. يواصل الملاك الإضافيون استلام التنبيهات فقط ولا يرون لوحة الإدارة.

### زر «🚀 تشغيل البوت»

أول زر في لوحة المستخدم ولوحة المالك يعيد تدفق الترحيب كاملاً (نفس `/start`): يرسل صورة الترحيب وبطاقة بيانات المستخدم ويحدّث القائمة. مناسب للعودة بعد إغلاق البوت دون كتابة الأوامر.

### الاشتراك الإجباري

يستطيع المالك الأساسي فرض الاشتراك في قنوات أو مجموعات أو بوتات قبل الاستخدام عبر «🔒 الاشتراك الإجباري». يفحص البوت العضوية عبر `getChatMember` قبل كل رابط، ويمنع غير المشتركين برسالة بأزرار انضمام مضمّنة وزر «✅ تحققت من الاشتراك». الاشتراكات محفوظة في مجلد `data/` وتبقى عبر عمليات إعادة التشغيل. يدعم الإضافة بـ `@username` أو `t.me` أو المعرّف الرقمي، ويرفض روابط الدعوة الخاصة.

### تنزيل الصور المتعددة

عندما يؤكد المصدر وجود أكثر من صورة في المشاركة (مثلاً كاروسيل TikTok)، يظهر زر **«🖼 تنزيل الصور كاملة (عدد)»** يُرسل الصور مجمعة (10 كحد أقصى لكل رسالة) بنفس ترتيب المصدر.

### صورة الترحيب

يرسل البوت مع كل `/start` أو «🚀 تشغيل البوت» لافتة ترحيب مولّدة برمجياً بتدرج لوني وأيقونة تنزيل. لاستخدام صورة مخصصة ضع `WELCOME_PHOTO_URL` في الأسرار، أو استخدم `WELCOME_DISABLE_PHOTO=1` لإرسال النص فقط.

## الحدود وضبط التزامن (آلاف المستخدمين)

يعمل Webhook بدلاً من الاستعلام المستمر، لذلك لا يحتاج البوت إلى عملية دائمة فقط لانتظار الرسائل. كل تنزيل يعمل في مجلد مؤقت فريد ومهمة بمعرّف فريد، فلا يحدث تعارض بين الطلبات حتى مع آلاف المستخدمين في نفس اللحظة: تنتظر الطلبات بترتيب الوصول (FIFO) وتبدأ تلقائياً مع توفر فتحات. قابل للضبط عبر الأسرار:

| المتغير | الافتراضي | الوصف |
| --- | --- | --- |
| `DOWNLOAD_MAX_CONCURRENT` | `2` | أقصى عدد تنزيلات متزامنة على الخادم (1–64). على الشريحة المجانية 256MB أبقِه 2 أو أقل. |
| `DOWNLOAD_MAX_WAITING` | `1000` | أقصى عدد طلبات منتظرة في الصف (10–50000). |
| `DATA_DIR` | `/app/data` | مجلد حفظ قوائم الاشتراك الإجباري (يُنشأ تلقائياً). |

يُقيّد البوت الملف إلى 45 ميغابايت لحماية الذاكرة وزمن الطلب. التنزيل يقتصر على المحتوى العام الذي تملك الحق في تنزيله أو استخدامه.

قد يتغير توفر الفيديو أو الصوت أو الصورة من الرابط نفسه دون تغيير في البوت، لأن المنصات قد تفرض تسجيل دخول أو قيود عمر أو حدود طلبات أو تغيّر بنية الرابط. لهذا يعرض البوت فقط الأنواع التي يؤكدها الفحص في لحظة الطلب، ويبلغ المستخدم والمالك برسالة مفهومة إذا منع المصدر التنزيل.
